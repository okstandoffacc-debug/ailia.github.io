# Настройка встроенного чата и push-уведомлений

## 1. Включить чат
1. В Supabase откройте **SQL Editor → New query**.
2. Выполните весь файл `messages-migration.sql`.
3. Откройте **Database → Publications → supabase_realtime** и включите таблицу `messages` (если её ещё нет в публикации).
4. Убедитесь, что у владельца магазина в `public.profiles` роль `admin`.
5. Загрузите все файлы из архива в GitHub Pages, сохранив папки и пути.

Чат работает внутри сайта. Покупателю нужно войти/зарегистрироваться; владелец видит входящие диалоги в кнопке «Сообщения».

## 2. Уведомления, когда сайт/браузер закрыт
Push требует VAPID-ключи и Edge Function на сервере; один только service worker не может отправить себе уведомление.

1. На компьютере с установленным Supabase CLI выполните `npx web-push generate-vapid-keys` и сохраните оба ключа.
2. В терминале из папки проекта выполните:

   ```bash
   supabase secrets set VAPID_PUBLIC_KEY="ВАШ_PUBLIC_KEY" VAPID_PRIVATE_KEY="ВАШ_PRIVATE_KEY" VAPID_SUBJECT="mailto:ВАШ_EMAIL"
   supabase functions deploy send-push
   ```

   Если CLI не привязан к проекту, сначала выполните `supabase link --project-ref qxaokgxjahojcqevlwhb`.
3. В `js/config.js` вставьте **только публичный** VAPID-ключ в `window.PUSH_CONFIG.vapidPublicKey`. Приватный ключ никогда не размещайте в GitHub или `config.js`.
4. Откройте опубликованный сайт по HTTPS под аккаунтом покупателя и аккаунтом владельца, откройте «Сообщения» и разрешите уведомления в запросе браузера. Сделать это нужно на каждом компьютере/профиле браузера.
5. Проверьте: отправьте тестовое сообщение с другого аккаунта. Уведомление при закрытом браузере зависит от настроек ОС/браузера и их разрешения на фоновые уведомления.

GitHub Pages сам по себе не выполняет серверный код. Поэтому для push нужен именно Supabase Edge Function; если ключи и функция не настроены, сообщения внутри сайта могут работать, но уведомления при закрытом браузере не будут отправляться.
